# ติดตั้งและทดสอบ US-1: สมัครสมาชิกและล็อกอิน

รอบนี้ทำเฉพาะ US-1 ตาม AC-1.1–AC-1.5 หน้า `/team` เป็นพื้นที่หลังเข้าสู่ระบบสำหรับต่อ US-2 ส่วน `/tasks` และ `/my` ตรวจการล็อกอินแล้วส่งผู้ใช้กลับ `/team` ยังไม่มีระบบทีมและงาน การจำกัดผู้รับงานเฉพาะสมาชิกทีมเป็น AC-3.1 และ AC-3.4 ในรอบ US-3

`docs/plan.md` และ `docs/requirements.md` คงเดิม ไม่มีการเปลี่ยนเกณฑ์ยอมรับ

## 1. ตั้งค่าฐานข้อมูลด้วยตัวเอง

1. ใน VS Code เปิด `supabase/migrations/20261114042000_us1_profiles.sql` และคัดลอกเนื้อหาทั้งไฟล์
2. เปิดโปรเจกต์ทดลองใน Supabase → **SQL Editor** → **New query** → วาง SQL → **Run** เพียงครั้งเดียว
3. เปิด **Table Editor** → `profiles` ตรวจว่ามี `user_id`, `display_name`, `email`, `created_at` และเปิด RLS (กติกาจำกัดแถวข้อมูลตามผู้ใช้)
4. หากพบข้อความว่าตารางหรือฟังก์ชันมีอยู่แล้ว ให้หยุดและส่งข้อความผิดพลาดให้ตรวจ ห้ามลบตารางหรือปิด RLS เพื่อแก้ปัญหา ไฟล์นี้ใช้สำหรับสร้างโครงสร้าง US-1 ที่ยังไม่มีอยู่
5. ใน Supabase → **Authentication** → **Sign In / Providers** → **Email** ปิด **Confirm email** แล้วบันทึก เฉพาะโปรเจกต์ workshop ตาม `docs/plan.md` เพื่อให้ AC-1.1 สมัครแล้วล็อกอินได้ทันที เมื่อใช้งานจริงให้เปิดกลับและเตรียมบริการส่งเมลยืนยัน

SQL สร้างโปรไฟล์พร้อมบัญชีในรายการเดียว ถ้าชื่อว่างจะไม่สร้างบัญชีค้าง อ่านโปรไฟล์ได้เฉพาะเจ้าของ ไม่อนุญาตให้ผู้ใช้เพิ่ม แก้ หรือลบโปรไฟล์โดยตรง อีเมลอ่านจาก Auth (ระบบบัญชี Supabase) เท่านั้น บัญชีอีเมลที่มีอยู่ก่อนติดตั้งจะได้รับโปรไฟล์ด้วย หากไม่มีชื่อเดิมจะใช้ส่วนหน้า `@` เป็นชื่อเริ่มต้นเฉพาะบัญชีเก่า

Codex ไม่ได้รัน SQL นี้กับฐานข้อมูลของคุณ การทดสอบ SQL อัตโนมัติใช้ฐานข้อมูล PostgreSQL จำลองในหน่วยความจำเท่านั้น

## 2. เปิดเว็บ

1. ตรวจว่ามี `.env.local` ซึ่งตั้ง `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` แล้ว ใช้ `.env.example` ดูชื่อค่าได้ ไม่ต้องเพิ่มค่าลับใหม่สำหรับ US-1 และไม่ต้องส่งเนื้อหา `.env.local` มาในแชท
2. เปิด Terminal ใน VS Code → เข้าโฟลเดอร์โปรเจกต์:

   ```powershell
   cd D:\AI_Engineer\Project_work\track-task-week10
   npm.cmd run dev
   ```

3. เปิด `http://localhost:3000/login` ถ้ามีเซิร์ฟเวอร์เดิมเปิดอยู่แล้วให้ใช้ตัวเดิม หรือหยุดด้วย `Ctrl+C` แล้วเปิดใหม่ ไม่ต้องเปิดหลายตัวบนพอร์ตเดียวกัน

## 4. ทดสอบความเป็นส่วนตัวด้วยสองบัญชี

1. สมัคร A ในเบราว์เซอร์ปกติ และ B ในหน้าต่างไม่ระบุตัวตนหรือเบราว์เซอร์อีกตัว แต่ละหน้าต่างต้องแสดงชื่อของบัญชีตัวเอง
2. ที่ Supabase → **Authentication** → **Users** คัดลอก User UID ของ A แล้วเปิด **SQL Editor** → **New query** วางคำสั่งข้างล่าง โดยแทน `UUID_ของ_A` ด้วย UID จริง แล้วกด Run:

   ```sql
   begin;
   set local role authenticated;
   select set_config('request.jwt.claim.sub', 'UUID_ของ_A', true);
   select user_id, display_name, email from public.profiles;
   rollback;
   ```

3. ผลอ่านต้องมีเฉพาะ A ไม่มี B แม้คำสั่งไม่ได้ใส่ตัวกรอง จากนั้นแทนด้วย UID ของ B แล้วรันใหม่ ต้องเห็นเฉพาะ B นี่เป็นการสวมบทบาทผู้ใช้เพื่อทดสอบ RLS; การอ่าน Table Editor ด้วยบัญชีผู้ดูแลอย่างเดียวไม่พิสูจน์สิทธิ์ของผู้ใช้เว็บ
4. ทดลองผู้ไม่ล็อกอินด้วยคำสั่งต่อไปนี้ ต้องถูกปฏิเสธสิทธิ์อ่าน:

   ```sql
   begin;
   set local role anon;
   select user_id, display_name from public.profiles;
   rollback;
   ```

   หากคำสั่งหยุดเมื่อเกิด error และยังค้าง transaction (รายการฐานข้อมูล) ให้รัน `rollback;` อีกครั้งแยกต่างหาก

## 5. ตรวจอัตโนมัติสำหรับผู้พัฒนา

ใช้ Node.js 22.18 ขึ้นไปสำหรับการทดสอบไฟล์ TypeScript โดยตรง เครื่องที่พัฒนารอบนี้ใช้ Node.js 26

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

- `npm.cmd test` ทดสอบการสมัคร/ล็อกอิน/ออกจากระบบผ่าน Supabase SDK จริงกับบริการ Auth จำลอง และรัน migration จริงบน PGlite (PostgreSQL ในหน่วยความจำ) เพื่อตรวจ RLS, trigger และสิทธิ์ ไม่สร้างบัญชีในโปรเจกต์ Supabase จริง
- หาก dev server ล็อกไฟล์ใน `.next` สามารถตรวจ build แยกโดยตั้งค่าเฉพาะคำสั่ง แล้วล้างตัวแปรเมื่อเสร็จ:

  ```powershell
  $env:NEXT_BUILD_DIR = '.next-check'
  npm.cmd run build
  Remove-Item Env:NEXT_BUILD_DIR
  ```

- ตรวจ HTTP (การตอบกลับของเว็บ) กับเซิร์ฟเวอร์ที่เปิดอยู่ได้ด้วยคำสั่งต่อไปนี้ โดยเปลี่ยน URL ตามพอร์ตจริง:

  ```powershell
  $env:TEST_BASE_URL = 'http://localhost:3000'
  node --test tests/routes.smoke.mjs
  Remove-Item Env:TEST_BASE_URL
  ```

ผลอัตโนมัติไม่ทดแทนการสมัครจริง การรับ cookie จริงหลังปิดเบราว์เซอร์ และการตรวจจอมือถือ ให้ทำตาราง AC ด้านบนหลังรัน SQL แล้ว ก่อนเริ่ม US-2 ให้อ่านรายการเปลี่ยนแปลงใน Source Control และ commit (บันทึกชุดการเปลี่ยนแปลง) ของ US-1 ตามกระบวนการทีม
