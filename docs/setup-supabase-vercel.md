# คู่มือตั้งค่า Supabase และ Vercel (สำหรับมือใหม่)

> ใช้คู่กับ workshop "สร้างระบบด้วย Codex" (ระบบติดตามงานทีม)
> **ส่วนที่ 1** ทำก่อนวันอบรม · **ส่วนที่ 2** ทำในวันอบรมตอนสร้างเว็บ · **ส่วนที่ 3** ทำตอนนำเว็บขึ้นออนไลน์
> ชื่อเมนูอ้างอิง ณ พฤศจิกายน 2026 ถ้าหน้าจอเปลี่ยน ให้มองหาคำที่ใกล้เคียง

## ภาพรวม: สองบริการนี้ทำอะไร

| บริการ | ทำหน้าที่ | เปรียบเหมือน |
|---|---|---|
| **Supabase** | เก็บข้อมูล (ฐานข้อมูล) และดูแลการสมัคร/ล็อกอิน | สมุดบัญชี + ยามเฝ้าประตู |
| **Vercel** | นำเว็บขึ้นอินเทอร์เน็ต ได้ลิงก์ให้คนอื่นเปิด | หน้าร้านที่คนเดินเข้ามาได้ |

ทั้งสองใช้**แบบฟรี**ได้ ไม่ต้องใส่บัตรเครดิต

## ส่วนที่ 1: ตั้งค่า Supabase (ทำก่อนวันอบรม ประมาณ 10 นาที)

### 1.1 สมัครบัญชี

1. เปิด **supabase.com** → กด **Start your project**
2. เลือก **Continue with GitHub** (สะดวกที่สุด ใช้บัญชี GitHub เดียวกับที่ใช้ใน workshop)
3. ถ้าถามให้สร้าง Organization ตั้งชื่ออะไรก็ได้ เช่น ชื่อตัวเอง → เลือกแผน **Free**

### 1.2 สร้างโปรเจกต์

1. กด **New project**
2. กรอกข้อมูล
   - **Project name:** `task-tracker` (หรือชื่ออื่นที่จำได้)
   - **Database Password:** กด **Generate a password** แล้ว**คัดลอกเก็บไว้ในที่ปลอดภัย** (วันนี้ยังไม่ได้ใช้ แต่ห้ามหาย)
   - **Region:** เลือก **Southeast Asia (Singapore)** เพื่อให้เว็บเร็วสำหรับคนในไทย
3. กด **Create new project** → รอประมาณ 1–2 นาทีจนหน้าจอพร้อม

> **ต้องเห็น:** หน้า Project Overview ของโปรเจกต์ที่เพิ่งสร้าง

### 1.3 ปิด Confirm email (สำคัญมาก)

แบบฟรีของ Supabase ส่งอีเมลยืนยันตัวตนได้น้อยมาก ถ้าไม่ปิด ผู้เรียนหลายคนจะสมัครแล้วล็อกอินไม่ได้

1. เมนูซ้าย → **Authentication**
2. **Sign In / Providers** → กดที่ **Email**
3. ปิดสวิตช์ **Confirm email** → กด **Save**

> **ต้องเห็น:** สวิตช์ Confirm email เป็นสีเทา (ปิด)
> เมื่อนำไปใช้งานจริงในอนาคต ให้เปิดกลับ และตั้งค่าระบบส่งอีเมล (SMTP) ของตัวเอง

### 1.4 เช็กว่าเจอค่าที่ต้องใช้ (ยังไม่ต้องคัดลอก)

วันอบรมจะใช้ 2 ค่านี้ ลองหาให้เจอก่อน

| ค่า | หาที่ไหน | หน้าตา |
|---|---|---|
| **Project URL** | ปุ่ม **Connect** ด้านบนของหน้าโปรเจกต์ | `https://abcdefgh.supabase.co` |
| **Publishable key** | **Project Settings** (ไอคอนเฟืองล่างซ้าย) → **API Keys** | `sb_publishable_...` |

> **อย่าสับสน:** ในหน้า API Keys จะมี **Secret key** (`sb_secret_...`) ด้วย **workshop นี้ไม่ใช้ และห้ามคัดลอกไปไว้ที่ไหน** เพราะรหัสนี้ข้ามกฎความปลอดภัยทุกข้อได้

## ส่วนที่ 2: เชื่อมเว็บในเครื่องกับ Supabase (ทำในวันอบรม)

ทำหลังจากสั่ง `$project-setup` เสร็จแล้ว

### 2.1 สร้างไฟล์ `.env.local`

1. ใน VS Code แถบซ้าย คลิกขวาที่ไฟล์ `.env.example` → **Copy** → คลิกขวาที่ว่าง → **Paste**
2. เปลี่ยนชื่อไฟล์สำเนาเป็น `.env.local` (มีจุดข้างหน้า)
3. เปิดไฟล์ `.env.local` แล้ววางค่าแทนตัวอย่าง

   ```text
   NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxx
   ```

4. กด **Ctrl+S** บันทึก

กติกาของไฟล์นี้
- ห้ามมีช่องว่างรอบเครื่องหมาย `=` และไม่ต้องใส่เครื่องหมายคำพูด
- ไฟล์นี้อยู่ในเครื่องเราเท่านั้น จะไม่ถูกส่งขึ้น GitHub (มี `.gitignore` กันไว้แล้ว)
- **ห้ามวางค่าในแชท** ห้ามแคปหน้าจอที่เห็นค่านี้

### 2.2 เปิดเว็บในเครื่อง

1. เมนู **Terminal → New Terminal**
2. พิมพ์ `npm run dev` แล้วกด Enter
3. เปิดเบราว์เซอร์ไปที่ **http://localhost:3000**

> **ต้องเห็น:** กล่องสีเขียว "เชื่อม Supabase สำเร็จ"
> **ถ้าเห็นกล่องสีเหลือง:** อ่านข้อความในกล่อง ส่วนใหญ่คือวางค่าผิดช่อง หรือแก้ไฟล์แล้วยังไม่ได้รันใหม่ ให้กด **Ctrl+C** ใน Terminal แล้วพิมพ์ `npm run dev` อีกครั้ง

### 2.3 วาง SQL ที่ Codex ให้มา

ทุกครั้งที่ Codex บอกว่ามีไฟล์ใหม่ใน `supabase/migrations/` ให้ทำดังนี้

1. เปิดไฟล์ `.sql` นั้นใน VS Code → **Ctrl+A** เลือกทั้งหมด → **Ctrl+C** คัดลอก
2. Supabase → เมนูซ้าย **SQL Editor** → **New query**
3. วาง (**Ctrl+V**) → กด **Run** (หรือ Ctrl+Enter)

> **ต้องเห็น:** ข้อความ `Success. No rows returned`
> **ถ้าขึ้น error:** อย่าแก้ SQL เอง คัดลอกข้อความ error ไปบอก Codex ว่า "รัน SQL แล้วขึ้น error นี้" (ระวังอย่าวาง key มาด้วย)
> ถ้าขึ้นหน้าต่างเตือนเรื่องคำสั่งที่อาจลบหรือแก้ข้อมูล ให้อ่านก่อน ถ้าเป็นไฟล์จาก Codex ในโปรเจกต์นี้ กดยืนยันได้

### 2.4 ดูข้อมูลและตรวจความปลอดภัย

| อยากรู้ | ไปที่ |
|---|---|
| ข้อมูลในตาราง (เช่น งานที่เพิ่งสร้าง) | **Table Editor** → เลือกตาราง |
| ผู้ใช้ที่สมัครแล้ว | **Authentication → Users** |
| ทุกตารางเปิด RLS หรือยัง | **Table Editor** → ตารางที่ยังไม่เปิดจะมีป้ายเตือน **RLS disabled** หรือ **Unrestricted** |
| คำเตือนด้านความปลอดภัยทั้งหมด | **Advisors → Security Advisor** |

> ใน Table Editor เราเห็นข้อมูลของ**ทุกคน**ทุกทีม เพราะเป็นเจ้าของโปรเจกต์ ผู้ใช้บนเว็บจะเห็นเฉพาะที่กฎ RLS อนุญาต จึงต้องดูแลบัญชี Supabase ให้ดี

## ส่วนที่ 3: นำเว็บขึ้น Vercel (ทำในวันอบรม ขั้นที่ 7)

### 3.0 ก่อนเริ่ม

- [ ] สั่ง `$security-check` ตรวจแล้ว ไม่มีปัญหาระดับ "สูง"
- [ ] สั่ง `$vercel-deploy` แล้ว Codex บอกว่า build ผ่าน
- [ ] Source Control → **Commit** → **Sync Changes** ส่งโค้ดล่าสุดขึ้น GitHub แล้ว

### 3.1 สมัคร Vercel

1. เปิด **vercel.com** → **Sign Up**
2. เลือกแผน **Hobby** (ฟรี สำหรับใช้ส่วนตัว) → ใส่ชื่อ
3. เลือก **Continue with GitHub** → อนุญาตให้ Vercel เข้าถึง GitHub

### 3.2 นำเข้าโปรเจกต์

1. หน้า Dashboard → **Add New…** → **Project**
2. ในรายการ **Import Git Repository** หา repo ของเรา → กด **Import**
   - ถ้าไม่เห็น repo: กด **Adjust GitHub App Permissions** แล้วเลือกให้ Vercel เห็น repo นี้
3. **Framework Preset** ต้องเป็น **Next.js** (Vercel เลือกให้อัตโนมัติ) ส่วนอื่นไม่ต้องแก้

### 3.3 ใส่ Environment Variables (ห้ามข้าม)

ในหน้าเดียวกัน กดเปิดหัวข้อ **Environment Variables** แล้วเพิ่มทีละตัว

| Key (ชื่อ) | Value (ค่า) |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ค่าเดียวกับใน `.env.local` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | ค่าเดียวกับใน `.env.local` |

- ชื่อต้องตรง**ทุกตัวอักษร** วิธีที่ง่ายที่สุดคือคัดลอกทั้งบรรทัดจาก `.env.local` ไปวางในช่อง Key (Vercel จะแยกชื่อกับค่าให้เอง)
- ถ้าทำงานเสริม US-6 (อีเมล) ให้เพิ่ม `GMAIL_USER` และ `GMAIL_APP_PASSWORD` ด้วย **ห้ามเติม `NEXT_PUBLIC_` ข้างหน้า**
- **ห้ามใส่ Secret key ของ Supabase**

### 3.4 Deploy

1. กด **Deploy** → รอประมาณ 1–3 นาที
2. ขึ้นหน้าแสดงความยินดี → กด **Continue to Dashboard**
3. คัดลอกลิงก์ใต้หัวข้อ **Domains** เช่น `https://task-tracker-xxxx.vercel.app`

> **ต้องเห็น:** เปิดลิงก์แล้วเจอกล่องสีเขียวเหมือนในเครื่อง

### 3.5 บอก Supabase ให้รู้จักลิงก์ใหม่

ถ้าไม่ทำขั้นนี้ บางหน้าที่เกี่ยวกับการล็อกอินจะพาผู้ใช้กลับไปที่ localhost

1. Supabase → **Authentication** → **URL Configuration**
2. **Site URL:** วางลิงก์ Vercel เช่น `https://task-tracker-xxxx.vercel.app` → **Save**
3. **Redirect URLs** → **Add URL** เพิ่ม 2 รายการ
   - `https://task-tracker-xxxx.vercel.app/**`
   - `http://localhost:3000/**`
4. กด **Save URLs**

### 3.6 ทดสอบบนลิงก์จริง

- [ ] สมัครบัญชีใหม่บนลิงก์ Vercel ได้ และล็อกอินได้
- [ ] สร้างทีม แล้วสร้างงานได้
- [ ] เปิดหน้าต่างไม่ระบุตัวตน สมัครอีกบัญชี → ต้อง**ไม่เห็น**งานของทีมแรก
- [ ] วางลิงก์ของคุณในแชทของห้องเรียน

## หลังจากนี้: การดูแลเว็บ

| สถานการณ์ | ทำอย่างไร |
|---|---|
| แก้โค้ดแล้วอยากให้เว็บจริงอัปเดต | Commit → **Sync Changes** แล้ว Vercel จะ deploy ใหม่ให้เองใน 1–3 นาที |
| แก้หรือเพิ่ม Environment Variables | Vercel → **Settings → Environment Variables** แก้ค่า → ไปที่ **Deployments** → กด **⋯** ของรายการล่าสุด → **Redeploy** (ค่าใหม่จะมีผลหลัง Redeploy เท่านั้น) |
| เว็บจริงพัง อยากรู้สาเหตุ | Vercel → โปรเจกต์ → **Logs** คัดลอกข้อความ error ไปให้ `$bug-fix` |
| deploy ใหม่แล้วพัง อยากย้อนกลับ | Vercel → **Deployments** → เลือกรุ่นที่ใช้ได้ → **⋯** → **Instant Rollback** (ย้อนแค่โค้ด ข้อมูลใน Supabase ไม่ย้อนตาม) |
| ไม่ได้ใช้เว็บนาน ๆ แล้วเว็บเชื่อมฐานข้อมูลไม่ได้ | Supabase แบบฟรีจะ**หยุดโปรเจกต์ชั่วคราว**ถ้าไม่มีการใช้งานประมาณ 1 สัปดาห์ เข้า Supabase แล้วกด **Restore project** |

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| ในเครื่องเห็นกล่องเหลือง "ยังไม่ได้ใส่ค่า" | ชื่อไฟล์ไม่ใช่ `.env.local` หรือยังไม่ได้รัน `npm run dev` ใหม่ | ตรวจชื่อไฟล์ (มีจุดข้างหน้า ไม่มี `.txt` ต่อท้าย) แล้วรันใหม่ |
| ในเครื่องเห็นกล่องเหลือง "เชื่อมไม่สำเร็จ" | วาง URL กับ key สลับช่อง มีช่องว่างเกิน หรือคัดลอกไม่ครบ | คัดลอกใหม่จาก Supabase ทั้งสองค่า |
| สมัครแล้วขึ้นว่า "Email not confirmed" | ยังไม่ได้ปิด Confirm email | ทำข้อ 1.3 แล้วสมัครด้วยอีเมลใหม่ |
| สมัครแล้วขึ้นว่าส่งอีเมลเกินกำหนด (rate limit) | ยังไม่ได้ปิด Confirm email | ทำข้อ 1.3 |
| ในเครื่องใช้ได้ แต่บน Vercel เห็นกล่องเหลือง | ลืมใส่ Environment Variables หรือชื่อสะกดผิด | ทำข้อ 3.3 ใหม่ใน Settings แล้ว **Redeploy** |
| Vercel build ไม่ผ่าน (Build Failed) | โค้ดมี error ที่ในเครื่องไม่เห็นตอน `npm run dev` | คัดลอก log สีแดงไปให้ Codex: "ใช้ $bug-fix build บน Vercel ไม่ผ่าน error ตามนี้" |
| ล็อกอินบนเว็บจริงแล้วถูกพาไป localhost | ยังไม่ได้ตั้ง URL Configuration | ทำข้อ 3.5 |
| ข้อมูลไม่แสดงบนหน้าเว็บ แต่ใน Table Editor มี | กฎ RLS ไม่อนุญาต หรือยังไม่ได้รัน SQL ล่าสุด | ใช้ `$bug-fix` **ห้ามปิด RLS** |

## ห้ามทำ (สรุป)

- ห้ามวาง Publishable key, Secret key, App Password หรือรหัสผ่านฐานข้อมูลในแชท หรือแคปหน้าจอที่เห็นค่าเหล่านี้
- ห้ามใช้ Secret key ในโปรเจกต์นี้ ทั้งใน `.env.local` และใน Vercel
- ห้ามปิด RLS เพื่อให้ข้อมูลแสดง แม้ Codex จะเสนอก็ตาม
- ถ้าสงสัยว่ารหัสหลุด: Supabase → **Project Settings → API Keys** สร้าง key ใหม่และยกเลิก key เดิม แล้วอัปเดตทั้ง `.env.local` และ Vercel
