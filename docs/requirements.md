# Requirements: ระบบติดตามงานทีม

> เอกสารนี้ผู้สอนเตรียมไว้ให้ ใช้เป็นข้อกำหนดของ `$supabase-feature` และเป็นเกณฑ์ทดสอบของ `$acceptance-test` อ้างถึงด้วยเลข US และ AC
>
> **ใน workshop:** US-1 ถึง US-4 ต้องทำ ส่วน US-5 และ US-6 เป็นงานเสริมสำหรับคนที่ทำทัน ทำตามลำดับเลข US-1 → US-2 → US-3 → US-4 → US-5 → US-6

## US-1 สมัครสมาชิกและล็อกอิน

ในฐานะผู้ใช้ ฉันต้องการสมัครและล็อกอินด้วยอีเมลและรหัสผ่าน พร้อมตั้งชื่อที่แสดง เพื่อให้เพื่อนร่วมทีมรู้ว่าใครเป็นใคร

**เกณฑ์ยอมรับ**
- AC-1.1 เมื่อกรอกชื่อที่แสดง อีเมล และรหัสผ่าน (อย่างน้อย 6 ตัวอักษร) ที่หน้า `/login` แล้วกดสมัคร ระบบสร้างบัญชี บันทึกชื่อที่แสดง และพาไปหน้า `/team` ในสถานะล็อกอินแล้ว
- AC-1.2 เมื่อล็อกอินด้วยรหัสผ่านผิด ระบบแสดงข้อความ "อีเมลหรือรหัสผ่านไม่ถูกต้อง" และยังอยู่ที่หน้า `/login`
- AC-1.3 เมื่อล็อกอินแล้ว แถบด้านบนแสดงชื่อที่แสดงของผู้ใช้และปุ่มออกจากระบบ กดแล้วกลับเป็นสถานะยังไม่ล็อกอิน
- AC-1.4 เมื่อปิดแล้วเปิดเบราว์เซอร์ใหม่ภายในวันเดียวกัน ยังอยู่ในสถานะล็อกอิน
- AC-1.5 ผู้ที่ยังไม่ล็อกอินเปิด `/team`, `/tasks` หรือ `/my` แล้วระบบพาไปหน้า `/login`

## US-2 สร้างทีม หรือเข้าร่วมทีมด้วยรหัสเชิญ

ในฐานะผู้ใช้ ฉันต้องการสร้างทีมใหม่ หรือเข้าร่วมทีมของเพื่อนด้วยรหัสเชิญ เพื่อทำงานร่วมกันในทีมเดียวกัน

**เกณฑ์ยอมรับ**
- AC-2.1 ผู้ที่ยังไม่มีทีมเปิด `/team` แล้วเห็น 2 ทางเลือก: "สร้างทีม" (กรอกชื่อทีม) และ "เข้าร่วมทีม" (กรอกรหัสเชิญ)
- AC-2.2 เมื่อสร้างทีม ผู้สร้างเป็น**หัวหน้าทีม** และหน้า `/team` แสดงชื่อทีม รหัสเชิญ 6 ตัวอักษร และรายชื่อสมาชิกพร้อมบทบาท (หัวหน้า / สมาชิก)
- AC-2.3 เมื่อกรอกรหัสเชิญที่ถูกต้อง ผู้ใช้เป็นสมาชิกของทีมนั้น และเห็นชื่อทีม รหัสเชิญ และรายชื่อสมาชิก ถ้ารหัสผิด ระบบแสดง "ไม่พบทีมจากรหัสนี้"
- AC-2.4 ผู้ใช้ 1 คนอยู่ได้ 1 ทีม ผู้ที่มีทีมแล้วไม่เห็นทางเลือกสร้างหรือเข้าร่วมทีม และถ้าส่งคำขอสร้างหรือเข้าร่วมทีมโดยไม่ผ่านหน้าจอ ระบบปฏิเสธพร้อมข้อความ "คุณมีทีมอยู่แล้ว"
- AC-2.5 กรอกชื่อทีมว่าง ระบบแสดง "กรุณากรอกชื่อทีม"
- AC-2.6 **คนนอกทีมไม่เห็นชื่อทีม รหัสเชิญ หรือรายชื่อสมาชิกของทีมนั้น** ทั้งบนหน้าจอและเมื่อ query ตาราง teams, team_members และ profiles ด้วย publishable key

## US-3 สร้างงานและมอบหมาย

ในฐานะหัวหน้าทีม ฉันต้องการสร้างงานและมอบหมายให้สมาชิก เพื่อให้ทุกคนรู้ว่าใครต้องทำอะไร ภายในเมื่อไร

**เกณฑ์ยอมรับ**
- AC-3.1 หัวหน้ากรอกชื่องาน (บังคับ), รายละเอียด (ไม่บังคับ), วันกำหนดส่ง (ไม่บังคับ) และเลือกผู้รับงานจากรายชื่อสมาชิกในทีม (รวมตัวเอง) แล้วกด "สร้างงาน" งานใหม่แสดงในหน้า `/tasks` ด้วยสถานะ "ยังไม่เริ่ม"
- AC-3.2 หน้า `/tasks` แสดงงานทุกชิ้นของทีม แบ่งเป็น 3 คอลัมน์ "ยังไม่เริ่ม / กำลังทำ / เสร็จแล้ว" แต่ละงานแสดงชื่องาน ชื่อผู้รับงาน และวันกำหนดส่ง (รูปแบบวันที่ไทย)
- AC-3.3 สมาชิกที่ไม่ใช่หัวหน้าไม่เห็นฟอร์มสร้างงาน และถ้าส่งคำขอสร้างงานโดยไม่ผ่านหน้าจอ ระบบปฏิเสธ
- AC-3.4 มอบหมายงานให้คนที่ไม่ใช่สมาชิกทีมไม่ได้ แม้จะส่ง `assignee_id` ของคนนอกทีมโดยไม่ผ่านหน้าจอ
- AC-3.5 ไม่กรอกชื่องาน ระบบแสดง "กรุณากรอกชื่องาน" และไม่สร้างงาน
- AC-3.6 ถ้าทีมยังไม่มีงาน แสดงข้อความ "ยังไม่มีงานในทีม" และผู้ที่ยังไม่มีทีมเปิด `/tasks` แล้วระบบพาไป `/team`
- AC-3.7 **สมาชิกทีม A ไม่เห็นงานของทีม B** ทั้งในหน้า `/tasks` และเมื่อ query ตาราง tasks ด้วย publishable key ของบัญชีในทีม A

## US-4 อัปเดตสถานะงาน

ในฐานะผู้รับงาน ฉันต้องการเปลี่ยนสถานะงานของฉัน เพื่อให้หัวหน้าและทีมเห็นความคืบหน้าโดยไม่ต้องถาม

**เกณฑ์ยอมรับ**
- AC-4.1 ผู้รับงานเปลี่ยนสถานะงานของตัวเองเป็น "ยังไม่เริ่ม", "กำลังทำ" หรือ "เสร็จแล้ว" ได้ และงานย้ายไปคอลัมน์ใหม่ทันทีหลังบันทึก
- AC-4.2 หัวหน้าทีมเปลี่ยนสถานะงานได้ทุกชิ้นในทีม
- AC-4.3 สมาชิกเปลี่ยนสถานะงานของคนอื่นไม่ได้ (ไม่เห็นตัวเลือก และถ้าส่งคำขอโดยไม่ผ่านหน้าจอ ระบบปฏิเสธ)
- AC-4.4 ผู้รับงานที่ไม่ใช่หัวหน้าแก้ได้**เฉพาะสถานะ** ถ้าส่งคำขอแก้ชื่องาน รายละเอียด วันกำหนดส่ง หรือผู้รับงาน ระบบปฏิเสธ
- AC-4.5 งานที่เลยวันกำหนดส่งแล้วและยังไม่เสร็จ แสดงป้ายสีแดง "เลยกำหนด" งานที่เสร็จแล้วไม่แสดงป้ายนี้

## US-5 งานของฉัน (งานเสริม)

ในฐานะสมาชิกทีม ฉันต้องการเห็นเฉพาะงานที่ได้รับมอบหมาย เพื่อรู้ว่าต้องทำอะไรก่อน

**เกณฑ์ยอมรับ**
- AC-5.1 หน้า `/my` แสดงเฉพาะงานที่ฉันเป็นผู้รับงาน เรียงตามวันกำหนดส่งที่ใกล้ที่สุดก่อน งานที่ไม่มีวันกำหนดส่งอยู่ท้ายสุด
- AC-5.2 งานที่เสร็จแล้วถูกซ่อนไว้ตอนเปิดหน้า และมีตัวเลือก "แสดงงานที่เสร็จแล้ว"
- AC-5.3 ถ้ายังไม่มีงานที่ได้รับมอบหมาย แสดงข้อความ "ยังไม่มีงานที่ได้รับมอบหมาย" พร้อมลิงก์ไป `/tasks`
- AC-5.4 เปลี่ยนสถานะงานจากหน้านี้ได้ โดยใช้กติกาเดียวกับ US-4

## US-6 อีเมลแจ้งเมื่อได้รับมอบหมายงาน (งานเสริม)

ในฐานะผู้รับงาน ฉันต้องการได้รับอีเมลเมื่อมีคนมอบหมายงานให้ เพื่อไม่พลาดงานใหม่

**เกณฑ์ยอมรับ**
- AC-6.1 เมื่อหัวหน้าสร้างงานสำเร็จ ภายใน 1 นาทีมีอีเมลถึงอีเมลของผู้รับงาน หัวเรื่อง "งานใหม่: <ชื่องาน>" เนื้อหามีชื่องาน, วันกำหนดส่ง (หรือ "ไม่มีกำหนด"), ชื่อทีม และชื่อผู้มอบหมาย
- AC-6.2 เมื่อสร้างงานไม่สำเร็จ ระบบไม่ส่งอีเมล
- AC-6.3 ถ้าส่งอีเมลไม่สำเร็จ งานยังถูกสร้างตามปกติ และหน้าจอแจ้ง "สร้างงานแล้ว แต่ส่งอีเมลแจ้งไม่สำเร็จ"
- AC-6.4 ผู้รับอีเมลคืออีเมลของผู้รับงานที่อ่านจากฐานข้อมูลเท่านั้น ส่งอีเมลผู้รับอื่นมากับคำขอแทนไม่ได้
- AC-6.5 ค่าที่ใช้ส่งอีเมล (`GMAIL_USER`, `GMAIL_APP_PASSWORD`) ใช้ฝั่ง server เท่านั้น ไม่ขึ้นต้นด้วย `NEXT_PUBLIC_` และไม่อยู่ในโค้ดหรือ git

> **วิธีส่งอีเมล:** ใช้เซิร์ฟเวอร์ส่งอีเมลของ Gmail (SMTP) กับ App Password ของ**บัญชี Gmail ที่สมัครไว้ทดลองโดยเฉพาะ** ห้ามใช้ Gmail ส่วนตัวหรือบัญชีที่ทำงาน เพราะ App Password เข้าบัญชีได้ทั้งบัญชี ส่งถึงผู้รับได้ทุกอีเมล ประมาณ 500 ผู้รับต่อวัน

## ข้อกำหนดที่ใช้กับทุก story

- NFR-1 ทุกตารางเปิด RLS และ browser ใช้ publishable key เท่านั้น
- NFR-2 ไม่มี key หรือรหัสผ่านอยู่ในโค้ดหรือ git
- NFR-3 ทุกหน้ามีสถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด และข้อความเป็นภาษาไทย
- NFR-4 ใช้งานได้บนมือถือ (กว้าง 375px ขึ้นไป) โดยไม่ต้องเลื่อนซ้ายขวา (บนจอแคบให้ 3 คอลัมน์ของ `/tasks` เรียงต่อกันลงมาได้)

## บัญชีสำหรับทดสอบ

ไม่ต้องเตรียมข้อมูลในตาราง ใช้ 3 บัญชี (หน้าต่างปกติ, หน้าต่างไม่ระบุตัวตน และเบราว์เซอร์อีกตัว หรือให้เพื่อนช่วย)

| บัญชี | ทำอะไร | ใช้ทดสอบ |
|---|---|---|
| A | สร้างทีม 1 เป็นหัวหน้า และสร้างงานมอบให้ B | AC-2.2, AC-3.1, AC-4.2 |
| B | เข้าร่วมทีม 1 ด้วยรหัสเชิญของ A | AC-2.3, AC-3.3, AC-4.1, AC-4.3, AC-4.4 |
| C | สร้างทีม 2 ของตัวเอง | คนนอกทีม (AC-2.6, AC-3.4, AC-3.7) |

สำหรับ AC-4.5 ให้ A สร้างงานที่มีวันกำหนดส่งเป็นเมื่อวาน
