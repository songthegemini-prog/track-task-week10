# ติดตั้งและทดสอบ US-2 ถึง US-4

งานรอบนี้เพิ่มทีม รหัสเชิญ รายชื่อสมาชิก กระดานงานสามสถานะ การมอบหมายเฉพาะสมาชิกทีม และการเปลี่ยนสถานะตามสิทธิ์ ยังไม่มีการแก้ไข/ลบงานผ่านเว็บ หน้า `/my` และอีเมลเป็นงาน US-5/US-6 ที่ยังไม่ทำ

## ติดตั้ง

1. ต้องติดตั้ง US-1 และสมัคร/ล็อกอินได้ก่อน ตาม `docs/testing-us1.md` ถ้ารัน SQL US-1 แล้วไม่ต้องรันซ้ำ
2. เปิด `supabase/migrations/20261114060000_us2_us4.sql` ใน VS Code คัดลอกทั้งไฟล์ → Supabase → **SQL Editor → New query** → วาง → **Run** เพียงครั้งเดียว ไฟล์นี้เพิ่มตาราง `teams`, `team_members`, `tasks` และกติกาสิทธิ์ ไม่แก้ migration US-1
3. ถ้าระบบแจ้งว่าตาราง/ฟังก์ชันมีอยู่แล้ว ให้หยุดและส่ง error มาตรวจ ห้ามลบข้อมูลหรือปิด RLS (ระบบจำกัดแถวข้อมูล) เพื่อให้ผ่าน
4. ใช้ค่าการเชื่อมต่อเดิมใน `.env.local` ไม่ต้องเพิ่ม key หรือค่าลับใด ๆ
5. เปิด Terminal ในโฟลเดอร์โปรเจกต์:

   ```powershell
   cd D:\AI_Engineer\Project_work\track-task-week10
   npm.cmd run dev
   ```

   ถ้าเปิดอยู่แล้วใช้เซิร์ฟเวอร์เดิม เปิด URL ตามบรรทัด `Local` เช่น `http://localhost:3000/login`

Codex เตรียมไฟล์ให้รันตามข้อกำหนด `AGENTS.md` และ skill `supabase-feature` ไม่รัน SQL กับฐานข้อมูลจริงแทนผู้ใช้ การทดสอบอัตโนมัติรัน migration บน PostgreSQL จำลองในหน่วยความจำเท่านั้น

## เตรียมบัญชี

| บัญชี | เปิดด้วย | การเตรียม |
|---|---|---|
| A | เบราว์เซอร์ปกติ | สร้างทีมหนึ่ง เป็นหัวหน้าทีม |

## ตรวจสิทธิ์ฐานข้อมูลโดยไม่ผ่านหน้าจอ

คัดลอก User UID ของ A/B/C จาก Supabase → **Authentication → Users** คัดลอก ID งานจาก Table Editor → tasks ใช้ SQL Editor สวมบทบาท `authenticated` เพื่อทดสอบ การอ่านด้วยสิทธิ์ผู้ดูแลตามปกติไม่พิสูจน์ RLS

ตัวอย่างทดสอบมอบงานให้คนนอกทีม (AC-3.4) แทนค่าข้อความในเครื่องหมายคำพูดด้วย UUID จริง:

```sql
begin;
set local role authenticated;
select set_config('request.jwt.claim.sub', 'UUID_A', true);
select public.create_task('ทดสอบผู้รับนอกทีม', null, null, 'UUID_C'::uuid);
rollback;
```

ต้องได้ error `ASSIGNEE_NOT_MEMBER` ไม่เกิดงานใหม่ เปลี่ยนผู้เรียกเป็น B และผู้รับเป็น B ต้องได้ `LEAD_REQUIRED` (AC-3.3)

ทดสอบแก้รายละเอียดพร้อมสถานะของ B (AC-4.4):

```sql
begin;
set local role authenticated;
select set_config('request.jwt.claim.sub', 'UUID_B', true);
update public.tasks
set title = 'พยายามแก้ชื่อ', status = 'done'
where id = 'UUID_งานที่รับโดย_B'::uuid;
rollback;
```

ต้องได้ `ONLY_STATUS_ALLOWED` ชื่องานและสถานะเดิมต้องไม่เปลี่ยน ลองเปลี่ยน `description`, `due_date`, `assignee_id` ด้วยเพื่อยืนยันข้อเดียวกัน

กรณีเกิด error แล้ว SQL Editor หยุดก่อนคำสั่งสุดท้าย ให้รัน `rollback;` อีกครั้งแยกต่างหาก

ทดสอบอ่านข้ามทีม: สวมบทบาท C แล้วอ่านทั้งสี่ตารางโดยไม่มีตัวกรอง ต้องเห็นเฉพาะทีมสอง สมาชิก/โปรไฟล์ทีมสอง และงานทีมสอง:

```sql
begin;
set local role authenticated;
select set_config('request.jwt.claim.sub', 'UUID_C', true);
select * from public.teams;
select * from public.team_members;
select user_id, display_name from public.profiles;
select * from public.tasks;
rollback;
```

ทดสอบ AC-2.4 โดยสวมบทบาท A แล้ว `select public.create_team('ทีมใหม่');` หรือ `select public.join_team('รหัสทีม');` ต้องได้ `ALREADY_IN_TEAM` ส่วนบัญชีไม่มีทีมที่ส่งสร้าง/เข้าทีมพร้อมกันสองหน้าต่างต้องสำเร็จเพียงหนึ่งคำขอ และมีสมาชิกภาพเพียงทีมเดียว

## ตรวจทั่วไปและคำสั่งสำหรับผู้พัฒนา

- จอ 375px ต้องไม่เลื่อนซ้ายขวา กระดานเรียงคอลัมน์ลงมา ชื่อยาวและรายละเอียดต้องตัดบรรทัด
- ทดสอบระหว่างโหลด ข้อมูลว่าง และกรณีเชื่อมต่อล้มเหลว ต้องมีข้อความไทยและลองใหม่ได้ กดบันทึกซ้ำระหว่างรอไม่ได้
- `npm.cmd test` ตรวจ US-1 และ US-2–US-4 รวมการปลอมผู้รับ การอ่านข้ามทีม การแก้หลายคอลัมน์ และวันไทย
- `npm.cmd run lint` ตรวจโค้ด และ `npm.cmd run build` ตรวจการประกอบเว็บ หาก `.next` ถูกล็อก ดูวิธีแยก build ใน `docs/testing-us1.md`
- ตรวจรายการเปลี่ยนแปลงใน Source Control แล้ว commit ก่อนเริ่ม US-5/US-6

การตรวจบัญชีจริงและรูปแบบบนเบราว์เซอร์ยังต้องทำหลังติดตั้ง SQL ไม่ถือว่าผ่านจากผลฐานข้อมูลจำลองเพียงอย่างเดียว
